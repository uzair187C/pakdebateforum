# PAK DEBATE FORUM (PDF) — DESIGN SYSTEM
# 18 — 3D PODIUM SPECIFICATION

Status: Signature-object specification / implementation handoff
Purpose: Define the intended website podium as a reusable visual system.

IMPORTANT:
This document describes the intended digital object from the approved visual direction.
The available reference is a rendered visual, not an original 3D model.
Therefore, values described as "target", "recommended", or "starting point" must be tuned during implementation rather than treated as measured source dimensions.

The podium is a BRAND OBJECT.

It is not:
- a normal content card
- a decorative stock image
- a generic debate podium
- a large rectangular box
- an always-spinning 3D model
- a substitute for the page's content

Its purpose is to establish PDF's visual identity immediately.

---

# 0. OBJECTIVE

The podium should communicate:

```text
authority
debate
education
precision
modernity
premium quality
institutional confidence
```

Visual character:

```text
mostly black
sculptural
slightly futuristic
elegant
minimal
architectural
cinematic
```

It should look appropriate in:

```text
a premium academic institution
a debate auditorium
a modern diplomatic stage
a high-end editorial website
```

---

# 1. REFERENCE PRIORITY

The reference image establishes the visual direction.

Highest-priority visual attributes:

```text
1. black silhouette
2. elegant non-boxy shape
3. central presentation
4. gold PDF branding
5. dramatic golden spotlight
6. deep black environment
7. premium shadow/depth
8. restrained material texture
```

Lower-priority implementation details may be tuned.

---

# 2. DO NOT COPY THE REFERENCE AS A FLAT POSTER

The website implementation should not simply place the reference image as the entire hero.

The goal is:

```text
reference image
↓
underlying visual language
↓
real or convincingly simulated 3D object
↓
interactive website object
```

---

# 3. PRIMARY SILHOUETTE

The podium should be:

```text
tall
narrow
visually grounded
vertically dominant
slightly sculptural
```

Avoid a conventional:

```text
wide rectangular lectern
```

---

# 4. NON-BOXY RULE

The object must have visible shape variation.

Preferred characteristics:

```text
tapered or subtly angled body
refined vertical planes
softened or chamfered transitions
controlled asymmetry only if visually justified
```

Do not introduce random futuristic shapes.

---

# 5. FUTURISTIC LEVEL

Target:

```text
10–20% futuristic
80–90% elegant/institutional
```

The podium should still immediately read as a podium.

---

# 6. FORM LANGUAGE

Use:

```text
clean planes
controlled curves
sharp but elegant edges
subtle bevels
deep recesses where useful
```

Avoid:

```text
excessive grooves
LED strips everywhere
science-fiction panels
mechanical details
gaming aesthetics
```

---

# 7. BODY COLOR

Primary:

```text
near-black
```

Not pure flat black everywhere.

The material needs enough tonal variation for the silhouette to remain visible.

---

# 8. BLACK MATERIAL

The black surface should respond to light.

It should show:

```text
edge highlights
soft gradients
subtle reflections
very restrained texture
```

---

# 9. WOOD CHARACTER

The original direction includes a wooden character.

However:

```text
wood grain = extremely subtle
```

The visitor should first see:

```text
black premium podium
```

and only then notice:

```text
material texture
```

---

# 10. WOOD GRAIN

Do not use large obvious planks.

Do not use rustic wood.

Do not use orange/brown wood.

Do not make the podium look like furniture.

---

# 11. MATERIAL ROUGHNESS

Target a sophisticated semi-matte finish.

Avoid:

```text
mirror black
cheap plastic
rubber
chrome
```

---

# 12. EDGE TREATMENT

Edges should catch the spotlight.

Use restrained beveling so highlights exist without making the object look inflated.

---

# 13. BEVEL PRINCIPLE

Bevels should primarily exist to:

```text
catch light
prevent razor-flat CG appearance
```

not to visibly round every edge.

---

# 14. BASE

The podium must visually sit on the environment.

Possible:

```text
subtle shadow
very dark floor contact
```

Avoid a bright platform unless specifically designed later.

---

# 15. GROUND CONTACT

A believable contact shadow is essential.

Without it the podium may appear to float.

---

# 16. SILHOUETTE TEST

Before materials are applied:

```text
render podium almost entirely black
```

The silhouette should still be recognizable.

If it isn't:

```text
shape needs improvement
```

Do not fix silhouette problems with lighting.

---

# 17. PROPORTION

Target a tall visual ratio.

Exact dimensions are implementation-dependent.

The visual objective is:

```text
height >> width
```

while still providing a stable base.

---

# 18. FRONT FACE

The front face is the identity surface.

It must remain:

```text
clean
legible
visually dominant
```

---

# 19. BRANDING AREA

The logo and text should sit toward the upper region of the front face.

Not:

```text
dead center of entire podium
```

Not:

```text
at the extreme top edge
```

---

# 20. LOGO

Use the approved PDF logo asset.

Do not redraw it from memory.

Do not alter proportions.

Do not stretch.

Do not add arbitrary effects.

---

# 21. LOGO PLACEMENT

Target:

```text
central horizontal alignment
upper portion of front face
```

---

# 22. LOGO SIZE

The logo must remain visible at:

```text
desktop hero scale
tablet scale
mobile hero scale
```

The final size is a responsive implementation variable.

---

# 23. TEXT

The text should identify:

```text
Pak Debate Forum Academy
```

when that is the approved hero wording.

The logo is the visual identifier.

The text is the supporting identity.

Therefore:

```text
logo
↓
Pak Debate Forum Academy
```

# 25. TEXT SIZE

```text
clearly readable
but subordinate to the overall object
```

It should not become the largest thing in the hero.

# 26. TEXT FONT

Do not permanently bake an unknown substitute font into the 3D texture until the final font is confirmed.

# 27. TEXT MATERIAL

```text
warm premium gold
```


# 28. GOLD MATERIAL

Gold should respond to light.

```text
controlled highlight
subtle depth
warm reflection
```

# 29. GOLD PLAQUE

The plaque should feel integrated into the podium.

Avoid a cheap sticker appearance.

---

# 30. PLAQUE DEPTH

Use subtle physical depth if implemented in actual 3D.

The plaque should not protrude excessively.

# 31. PLAQUE EDGES

A small edge highlight can communicate physicality.

---

# 32. PLAQUE BACKGROUND

The plaque should remain compatible with the black podium.

Preferred:

```text

```

or a gold treatment consistent with the approved reference.

---

# 33. GOLD CONTRAST

The gold must remain legible against:

```text
black
deep shadow
spotlight
```

---

# 34. LIGHTING OBJECTIVE

The lighting should make the podium visible without destroying its darkness.

---

# 35. PRIMARY LIGHT

A single dominant golden spotlight comes from above.

# 36. PRIMARY SPOTLIGHT

Characteristics:

```text
warm
directional
focused
soft-edged enough to feel cinematic
```

The spotlight should:

```text
reveal silhouette
catch edges
illuminate branding
create depth
```

---

# 38. SPOTLIGHT INTENSITY

Do not make it so bright that:

```text
black becomes gray
gold becomes yellow-white
background becomes visible
```

---

# 39. SPOTLIGHT COLOR

Warm gold.

Exact RGB/temperature is implementation-tunable.

---

# 40. SECONDARY LIGHT

Only minimal environmental fill should exist.

---

# 41. FILL LIGHT

Purpose:

```text
preserve shape information in deep shadow
```

Not:

```text
brighten the whole object
```

---

# 42. RIM LIGHT

Optional and extremely subtle.

Can help separate the silhouette from black.

---

# 43. RIM LIGHT RULE

If the rim light becomes obvious as a bright outline:

```text
reduce it
```

---

# 44. BACKGROUND

Target:

```text
near-black / pitch-black
```

with subtle atmospheric variation.

---

# 45. BACKGROUND MUST NOT COMPETE

No busy:

```text
stars
particles
architecture
textures
patterns
```

unless separately approved.

---

# 46. GOLD ATMOSPHERE

A tiny amount of gold atmospheric light is allowed.

It should feel like:

```text
light in air
```

not:

```text
gold fog
```

---

# 47. SHADOW

The podium should cast a deep shadow.

---

# 48. SHADOW CHARACTER

Shadow should be:

```text
soft enough to feel photographic
deep enough to create drama
directionally consistent with spotlight
```

---

# 49. SHADOW DIRECTION

Must match the actual light direction.

Never fake a shadow that contradicts the spotlight.

---

# 50. CONTACT SHADOW

Strong enough to ground the object.

---

# 51. ENVIRONMENT

The default environment is intentionally sparse.

The podium should feel isolated on a dark stage.

---

# 52. STAGE

Do not automatically add:

```text
curtains
auditorium seats
microphones
flags
crowd
lectern accessories
```

The object itself is the focus.

---

# 53. MICROPHONE

No microphone by default.

The podium identity is stronger without unnecessary accessories.

---

# 54. DESKTOP COMPOSITION

Hero layout should leave enough room for:

```text
navigation
headline
supporting text
CTA
podium
```

The podium should not occupy the entire viewport.

---

# 55. DESKTOP PODIUM POSITION

Preferred:

```text
right side / visual anchor
```

if the hero text is left aligned.

Alternative:

```text
centered
```

when the page composition is intentionally centered.

---

# 56. HERO BALANCE

The podium must balance the text block.

Think:

```text
text = communication
podium = identity
```

---

# 57. PODIUM OVERLAP

Controlled overlap with the hero background is encouraged.

Avoid overlap that hides text.

---

# 58. MOBILE COMPOSITION

On mobile:

```text
text first
visual second
```

unless the final page design intentionally chooses a centered hero.

---

# 59. MOBILE PODIUM WIDTH

Do not allow the podium to fill the entire screen width.

Maintain breathing room.

---

# 60. MOBILE PODIUM HEIGHT

Use viewport-relative sizing carefully.

Do not create:

```text
huge vertical scroll before CTA
```

---

# 61. MOBILE LOGO

Logo and plaque must remain readable.

---

# 62. MOBILE CROPPING

The podium may be cropped slightly for visual drama only if:

```text
brand remains visible
silhouette remains understandable
```

---

# 63. TABLET

Tablet framing should sit between desktop and mobile.

Do not use desktop camera blindly.

---

# 64. RESPONSIVE CAMERA

If using true 3D:

camera parameters should adapt to:

```text
viewport aspect ratio
```

---

# 65. CAMERA OBJECTIVE

The camera should preserve:

```text
podium silhouette
branding visibility
visual center
```

---

# 66. CAMERA FOCAL POINT

Default focal target:

```text
upper-middle front face
```

not the base.

---

# 67. CAMERA PERSPECTIVE

Use enough perspective to create depth.

Do not make the podium look excessively distorted.

---

# 68. CAMERA DISTANCE

Tune based on final mesh proportions.

Do not hardcode arbitrary values before the model exists.

---

# 69. CAMERA MOTION

Default idle:

```text
almost static
```

---

# 70. CAMERA PARALLAX

During scroll, camera movement may be used.

Keep subtle.

---

# 71. POINTER RESPONSE

Desktop-only optional interaction.

Possible:

```text
pointer position
→ small camera/object orientation shift
```

---

# 72. POINTER RESPONSE LIMIT

The front branding should remain readable.

---

# 73. POINTER RESPONSE SPEED

Smooth pointer movement.

No snapping.

---

# 74. POINTER RESPONSE MOBILE

Disabled.

---

# 75. SCROLL RESPONSE

The podium may:

```text
shift depth
move slightly
reduce scale
fade/reframe
```

as hero exits.

---

# 76. SCROLL RESPONSE RULE

It should feel anchored to the stage.

It should not feel like a floating sticker following the page.

---

# 77. IDLE ANIMATION

Optional:

```text
subtle light movement
```

---

# 78. IDLE ANIMATION FREQUENCY

Slow enough that visitors do not consciously notice repetition.

---

# 79. NO CONSTANT SPIN

The podium must not continuously rotate 360 degrees.

This is a critical rule.

---

# 80. MATERIAL DETAIL

Texture should be visible primarily at close visual inspection.

---

# 81. TEXTURE SCALE

Wood grain must be physically plausible.

---

# 82. TEXTURE CONTRAST

Very low.

---

# 83. TEXTURE DIRECTION

Follow the podium's structural form.

Avoid a single texture simply projected over the entire object without regard for orientation.

---

# 84. NORMAL/BUMP

Optional subtle normal detail.

Do not create exaggerated roughness.

---

# 85. ROUGHNESS MAP

May vary slightly.

---

# 86. METALLIC

Wood:

```text
very low / non-metallic
```

Gold:

```text
metallic treatment
```

Exact shader implementation can vary.

---

# 87. GOLD ROUGHNESS

Avoid perfect mirror gold.

Premium gold is controlled, not chrome-like.

---

# 88. LIGHT REFLECTION

Gold should catch the spotlight more clearly than the black body.

---

# 89. BLACK BODY REFLECTION

Reflection should be restrained.

---

# 90. AMBIENT OCCLUSION

Can improve grounding and recess depth.

---

# 91. SHADOW QUALITY

Desktop can use higher quality shadows.

Mobile may use simplified shadows.

---

# 92. MOBILE PERFORMANCE

Possible reductions:

```text
shadow resolution
texture resolution
post-processing
lighting complexity
polygon count
```

---

# 93. MOBILE 3D THRESHOLD

If the device cannot maintain acceptable performance:

```text
fallback to static image
```

---

# 94. STATIC FALLBACK

It must preserve:

```text
same composition
same black/gold treatment
same branding
same lighting direction
```

---

# 95. FALLBACK LOADING

Recommended:

```text
static image appears immediately
3D loads behind/over it
3D becomes visible when ready
```

---

# 96. FALLBACK FAILURE

If 3D fails:

```text
keep static image
```

No error message is needed for the visitor.

---

# 97. ACCESSIBILITY

If the podium is decorative:

```text
aria-hidden
```

or equivalent semantic treatment.

---

# 98. INTERACTIVE PODIUM

Only make it semantically interactive if it performs a useful function.

---

# 99. KEYBOARD

A purely decorative podium must not receive keyboard focus.

---

# 100. REDUCED MOTION

Use:

```text
static podium
minimal fade
```

---

# 101. REDUCED MOTION 3D

Do not run unnecessary continuous camera/object animation.

---

# 102. WEBGL FAILURE

Never show:

```text
empty canvas
black rectangle
broken WebGL message
```

when a fallback can be used.

---

# 103. MODEL FORMAT

Preferred production architecture:

```text
optimized glTF / GLB
```

if actual 3D is used.

---

# 104. MODEL OPTIMIZATION

Optimize:

```text
geometry
textures
materials
draw calls
```

without visibly damaging silhouette quality.

---

# 105. TEXT IN 3D

Prefer not to bake critical text into a texture unless necessary.

Possible alternatives:

```text
HTML overlay
3D text
texture
```

The final choice depends on the visual requirement.

---

# 106. HTML BRANDING OPTION

Advantages:

```text
perfect text rendering
responsive sizing
accessible content if semantic
easy font updates
```

Potential disadvantage:

```text
may not follow surface perspective automatically
```

---

# 107. TEXTURE BRANDING OPTION

Advantages:

```text
physically integrated
consistent with surface
```

Potential disadvantages:

```text
harder responsive scaling
font baked into asset
less flexible
```

---

# 108. RECOMMENDED BRANDING STRATEGY

If the plaque remains visually front-facing:

```text
use carefully positioned HTML/SVG overlay
```

or an SVG texture with the approved logo/font.

If the plaque becomes genuinely angled/3D:

```text
use a surface-aligned texture or geometry
```

```text
pointer X/Y
```
